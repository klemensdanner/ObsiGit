- zentrale constraint logik
- datenintensive algorithmen
können gut in die Datenbank verfrachtet werden

- kompillierter Code liegt dann als Datenbankobjekt vor.
- darauf können genauso Rechte vergeben, wie auch auf Tabellen
### Vorteile:
- Performanz
- Datenbankmigration schwierig, weil verschiedene Datenbanken unterschiedliche Sprachen erlauben (z.B. oracle: pl/sql; java)

#### PL/SQL
- pl/sql engine teilt einen pl/sql block in prozeduralen Teil und SQL Teil
- blockorientiert, statische typprüfung
#### Blocktypen
- anonym: wird nur ausgeführt und ergebnis returnt, nicht gespeichert in der Datenbank
- Gespeicherte Prozeduren, können explizit aufgerufen werden
- DB Trigger: kann man nicht manuell aufrufen, nur von der Datenbank durch ein Event aufrufbar

#### Deklaration

%TYPE übernimmt einen typ von der Datenbank
%ROWTYPE erstellt einen Record typ aus mehreren spalten

Record kann man auch manuell machen, mit IS RECORD

DDL-Anweisungen sind etwas speziell:
- EXECUTE IMMEDIATE 'DDL-Anweisung';
- Warum: alles bis dahin muss commitet sein - danach wird ein DDL automatisch committet - deshalb wurde das so umgesetzt
